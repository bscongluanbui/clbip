# Nâng cấp repo Linux/Docker từ các cải tiến của fork Mac — 08/10/2026

## Các thay đổi

- **Tạo pool theo batch:** thêm tối đa 16 alias mỗi batch; tối đa 8 tác vụ xác minh DAD và Internet chạy đồng thời. Mỗi alias vẫn được ghi nhật ký trước khi tạo. Khi một tác vụ lỗi hoặc Stop được yêu cầu, tool chờ tất cả tác vụ đang chạy kết thúc trước khi rollback/dọn địa chỉ. Chỉ kích hoạt pool khi mọi địa chỉ đạt kiểm tra; không dùng pool mới xác minh một phần.
- **Progress và status nhẹ:** Alias/DAD/Egress, giai đoạn, thời gian chạy, heartbeat và lỗi. Các số liệu cached trong lúc thao tác được phân biệt với kiểm tra health thực; một snapshot nhẹ không thay thế bằng chứng readiness.
- **Nguồn và card mạng rõ hơn:** hiển thị interface, loại card, IPv4/IPv6 quan sát, trạng thái kết nối và lý do chưa có IPv6 ứng viên. IPv6 quan sát được không mặc nhiên là IPv6 đã xác minh Internet.
- **Xác nhận đổi nguồn:** `source_change_confirmations` mặc định 2 và `source_poll_interval` mặc định 5 giây; thiết lập trong giao diện. Theo dõi prefix mới trước khi tái tạo pool để hạn chế thay đổi nhất thời. Việc đổi địa chỉ SLAAC/privacy nhưng vẫn cùng `/64` không tự tạo lại toàn bộ pool.
- **URL truy cập/export:** hiển thị địa chỉ dashboard thực theo bind và các địa chỉ LAN/Tailscale quan sát được. Export wildcard chọn địa chỉ host sử dụng được thay vì xuất `0.0.0.0` hay placeholder; không mở thêm listener và không tự cấu hình Tailscale Serve.
- **Đổi mật khẩu dashboard trên UI:** mật khẩu là tùy chọn, không áp đặt độ dài tối thiểu hay yêu cầu độ phức tạp. Nhập mật khẩu hiện tại, mật khẩu mới và xác nhận; để trống cả mật khẩu mới/xác nhận để tắt đăng nhập bằng mật khẩu. Worker ghi atomic; các phiên cũ bị thu hồi khi credential thay đổi. Lưu lại cùng mật khẩu là thao tác không đổi trạng thái. Thao tác không thay credentials proxy hay tái tạo pool.
- **Doctor đọc-only**, **helper đổi cổng dashboard** có preflight/backup/rollback, và **preview UI offline** được bổ sung bên dưới.
- **`maxconn` mặc định 64** trong cấu hình 3proxy, áp dụng cho mỗi dịch vụ/listener được khai báo sau lệnh này; dual có hai listener. Đây không phải giới hạn tổng 64 cho cả shard hay cam kết throughput. [Tài liệu 3proxy](https://3proxy.org/doc/man3/3proxy.cfg.3.html) mô tả giới hạn này ở mục `maxconn`.

Các tính năng Linux/Docker đang có được giữ lại: SQLite transaction/journal/ownership, Stop bền vững, reboot recovery, HTTP/SOCKS5/dual, multiuser, ACL, rotate, speedtest, Telegram, và LAN/routed prefix. Không sao chép backend `ifconfig`/`launchd` của macOS.

## Áp dụng maxconn 64 cho cấu hình đã lưu

Default mới không ghi đè một giá trị mà người dùng đã lưu trước đây. Trong UI vào **Tools → Connection settings → Max connections**, đặt **64** và lưu, hoặc chạy tại thư mục repo đang triển khai:

```bash
docker compose exec -T worker python -c "from rpc import WorkerClient; print(WorkerClient().call('save_settings', {'max_connections': 64}))"
```

Đây là thay đổi cấu hình thực trên deployment đang chạy, có thể reload các tiến trình proxy qua transaction. RPC phản hồi là bằng chứng thao tác; kiểm tra `/readyz` và health sau khi áp dụng. Lần nâng cấp mã nguồn này không tự SSH hay sửa cấu hình của server khác.

## Doctor trên Linux host

Yêu cầu Python 3.10+, Docker Compose v2 và quyền truy cập Docker của tài khoản vận hành. Script không cần cài các package Python dashboard trên host; nó kiểm tra runtime bên trong container.

```bash
python3 scripts/doctor.py --project-dir /home/ubuntu/ipv6
# Từ chính thư mục repo có thể bỏ --project-dir:
python3 scripts/doctor.py
```

Doctor đọc Compose config, inventory/health, UID/GID và dependencies của hai role, import/login dashboard dưới đúng identity, mount permissions, RPC worker có token, `/livez` và `/readyz`, listener owner qua `ss`, và 60 dòng log gần nhất. Nó không gọi Start/Stop, không tạo/xóa IPv6, không đổi password hay trạng thái persistent. Command output và log được redacted; kết quả kết thúc bằng:

```text
CLASSIFICATION: healthy
DOCTOR: result=OK failed_checks=0
```

Đây là dạng kết quả kỳ vọng khi deployment thực sự healthy, không phải báo cáo chạy trên server trong lần nâng cấp này. Exit code 0 nghĩa là các check bắt buộc đạt; 1 nghĩa là có check lỗi. `dashboard_port_conflict` chỉ được phân loại khi log báo cổng bận và dashboard hiện không healthy; lỗi cũ trong log không ghi đè trạng thái healthy hiện tại.

## Đổi cổng dashboard, không tác động worker

```bash
python3 scripts/change_dashboard_port.py 7071 --project-dir /home/ubuntu/ipv6
```

Helper:

1. Lấy lock để chặn hai helper sửa đồng thời; resolve Compose từ đúng project directory.
2. Thử bind cổng mới với **GUI_BIND đang cấu hình**, không tự đổi bind host. Cổng bận thì giữ nguyên `.env` và dịch vụ.
3. Backup `.env` và các file Compose/override đang dùng vào `.dashboard-port-backups/<timestamp-id>/`; lưu manifest, quyền truy cập riêng và ghi `.env` atomic. Những biến/comment khác được giữ lại.
4. Resolve lại Compose để xác nhận port mới và bind không đổi. Nếu override hardcode cổng, helper rollback `.env` và không recreate container.
5. Chỉ chạy `up -d --no-deps --force-recreate --no-build --pull never dashboard`. Worker đang dừng vẫn được giữ dừng; không start/restart worker, không sửa pool.
6. Xác minh `/livez`; nếu recreate hoặc liveness lỗi, phục hồi `.env` chính xác và recreate riêng dashboard ở cổng cũ. Thông báo nói rõ khi rollback liveness chưa được xác nhận.

Với file Compose hoặc env khác tên:

```bash
python3 scripts/doctor.py --project-dir /home/ubuntu/ipv6 --compose-file docker-compose.yml --compose-file docker-compose.override.yml --env-file .env
python3 scripts/change_dashboard_port.py 7071 --project-dir /home/ubuntu/ipv6 --compose-file docker-compose.yml --compose-file docker-compose.override.yml --env-file .env
```

Các file của helper đổi cổng phải ở trong project directory. Nếu dùng shell export `GUI_PORT`, helper loại giá trị đó **chỉ khỏi môi trường của subprocess** để `.env` mới có tác dụng; shell gọi bên ngoài không bị sửa. Biến `GUI_BIND` được giữ nguyên. Kiểm tra bind chỉ chứng minh cổng rảnh ở thời điểm preflight; xung đột xuất hiện sau đó sẽ được phát hiện ở bước recreate/liveness và rollback.

## Mật khẩu persistent trong Docker

Compose bổ sung volume **`dashboard-credentials`**. Worker mount RW, dashboard mount RO; `DASHBOARD_PASSWORD_PATH` trỏ đến credential file riêng trong volume. `ADMIN_PASSWORD_FILE` vẫn là Docker secret chỉ đọc dùng bootstrap, không bị atomic-replace trên mountpoint.

Worker khởi tạo một lần khi volume chưa có credential; file hiện hữu không bị ghi đè bởi restart/bootstrap. Volume mới cần được mount đồng nhất vào cả hai role khi triển khai image mới. Không dùng `docker compose down -v` để cập nhật thông thường, vì lệnh đó xóa cả trạng thái và credential volumes.

Để khởi tạo một deployment mới mà không yêu cầu mật khẩu dashboard:

```bash
python3 scripts/init_secrets.py --no-dashboard-password
```

`service_token` và `secret_key` vẫn được tạo cho IPC/session; file `admin_password` rỗng là cấu hình hợp lệ, không phải thiếu credentials. Khi credential volume đã có mật khẩu, thay file bootstrap không ghi đè mật khẩu đó: dùng phần đổi mật khẩu trên UI, để trống mật khẩu mới/xác nhận để tắt đăng nhập. Doctor không coi giá trị mật khẩu rỗng là lỗi và theo redirect `/login` đến dashboard khi đăng nhập bằng mật khẩu đã tắt.

## Preview UI trên máy phát triển

```bash
python scripts/preview_dashboard.py --port 17070
```

Mở `http://127.0.0.1:17070` và dùng mật khẩu demo in trong terminal. Runner chỉ bind **127.0.0.1**, không import network engine hoặc gọi worker thật. Status, pool 100 proxy, interface, health và log đều là dữ liệu mô phỏng (`2001:db8::/32`). Login/logout chỉ đổi phiên demo; mọi control/password mutation và export đều bị chặn. Địa chỉ LAN/Tailscale trong dữ liệu demo không phải endpoint đã được kết nối hoặc xác minh.

## Kiểm thử offline

```bash
python -B -m unittest discover -s tests -p test_ops_upgrade.py -v
python -B -m unittest discover -s tests -p 'test_*.py'
node --test tests/test_frontend.js
node tests/test_frontend_upgrade.js
```

`test_ops_upgrade.py` dùng Docker runner giả, kiểm tra healthy/port conflict/redaction/identity/preflight, lock, backup, rollback, worker giữ nguyên và preview read-only. Fixture temp nằm dưới `.test-tmp` trong workspace; không gọi Docker thật, không tạo alias thật và không chứng minh tốc độ tạo pool hoặc acceptance Linux production. Kiểm thử Linux integration/role và reboot/renumber trên mạng thực được thực hiện riêng khi triển khai.
